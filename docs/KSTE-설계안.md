# KSTE (Korean Simplified Technical Korean) 설계안 v0.1

작성일: 2026-10-04
목적: ASD-STE100의 구조를 한국어 기술문서에 옮긴 작문 규칙과, 그 규칙을 기계적으로 검사하는 Claude Code 플러그인(린터)을 정의한다.

---

## 0. 핵심 결론

**제1원칙: 독자가 추론할 것을 남기지 않는다.** 짧게 쓰는 것이 목적이 아니다. 독자 머릿속에서 일어날 해석 작업(생략된 조사·서술어 채우기, 어려운 말 풀기, 중의 해소)을 글쓴이가 미리 한다. STE의 모든 규칙과 국어원의 모든 지침이 이 한 문장에서 나온다. 길이 제한은 파생 지표다.

1. **한국어 통제언어 표준은 없다.** 민간 항공 AMM은 한국에서도 영어 STE 원문을 쓰고, 국방 기술교범 지침은 서식·용어 일관성만 다루며, 국립국어원 공공언어 지침은 질적 기준만 있고 어절 수 같은 수치 기준이 없다. 따라서 KSTE는 "번역"이 아니라 "표준들을 조합한 새 규칙 집합"이며, 각 규칙마다 출처를 명시한다.
2. **STE의 구조 규칙(문장·절차·서술·안전지시·구두점)은 그대로 옮긴다.** 사전 규칙(승인어 875개)은 한국어에 대응물이 없으므로, 국립국어원 **번역투·중복·피동 사전**과 **프로젝트 용어 통일표**로 대체한다. 이것이 사실상 Karpathy의 "80% 모드"와 같다.
3. **엄격 모드는 정보를 깎는다.** 비공식 실험에서 "ASD-STE100 엄수" 지시는 핵심 사실의 46.8%를 잃었고, 느슨한 지시는 8.5%만 잃었다. KSTE는 **정보 보존 검사**를 린터에 넣는다. 짧아졌다고 통과시키지 않는다.
4. **"보기엔 STE 같지만 규칙을 어긴다"는 ASD 경고의 해법은 모델 밖의 린터다.** 모델이 쓰고, 린터가 잡고, 모델이 지적된 줄만 고치고, 기계가 못 보는 규칙은 사람에게 명시적으로 넘긴다.
5. **형태소 분석은 Node 안에서 가능하다.** Kiwi WASM(`kiwi-nlp` 0.24.0, Apache-2.0)이 Windows에서 실측 동작했다. 이중피동 `저장되어집니다 → 되/XSV 어/EC 지/VX`가 품사 패턴으로 결정적으로 잡힌다. 모델 110MB는 별도 설치하고, 없으면 정규식 계층으로 폴백한다.

### 1.2 국립국어원 공공언어 지침

PDF 5종(2013 교재, 2019 진단 보고서, 2021 지침 연구보고서 425쪽, 2022 한눈에 개정판, 2025 전문용어 표준화 안내서)을 직접 추출했다.

- **문장 길이**: 수치 기준 없음. "핵심 내용 하나에 문장 하나", "한 문장에 한두 가지 정보", "연결어미로 길게 이은 문장은 진단 대상". 간결성 저해 4유형: 한 문장에 너무 많은 내용 / '-하다' 생략 개조식 나열 / 쉼표·연결어미 나열 / 기호로 행만 바꾼 한 문장.
- **피동 정의(2021 보고서)**: 접미사 `-이-/-히-/-리-/-기-/-되다/-받다/-당하다`, 통사 구성 `-아/어지다`. 사동 `-시키다/-게 하다`. 이중피동 "보여지다" 부적절 명시.
- **번역투(명시된 것만)**: `~에 의해(서)`, `~에 의한`, `~에 있어(서)`, `~에 있다(=이다)`, `~에 대하여/대한(→에게)`, `~을 통해/통한`, `~을 필요로 하다`, `~에 위치하다`, 추상 주어의 `존재하다/부재하다`, `~에 갈음하다`, `~을 득하다`, `타/동/본/당해/금번/익일`, 사물 주어 능동문, 이중부정 `~에 의하지 아니하고는`.
- **중복(2013 p.168)**: 과반수 이상, 약 N여, 유무 여부, 접수받다, 사전에 미리, 기간 동안, 매 N마다, 존재하고 있다, 피해를 입다, 다시 반복하다 등 약 60쌍.
- **명사 나열**: "조사·어미·'-하다'를 지나치게 생략하지 않음", "동사 중심으로 풀어쓰기". 예: 「노인 복지 종합 계획을 수립, 시행」→「수립하여 시행」.
- **약어**: 로마자 단독 금지. 최초 1회 `한글[약어]` 또는 `한글(원어)`. 법적 근거 국어기본법 14조.
- **숫자·단위**: 아라비아 숫자, 단위 명사 띄어쓰기(50만 명), 날짜 `2019. 3. 9.`, 시간 `16:14`, 만 단위 끊기.
- **2019 진단 오류 분류**(린터 카테고리로 직접 사용): ①중복 ②접속 ③호응 ④구성·어순(번역투=과도한 피·사동) ⑤생략.
- **2025 전문용어 표준화 기준**: 문법성·투명성·간결성·친숙성·일관성·**일의성(한 용어 = 한 개념)**. STE "one word one meaning"과 같다. 용어집 스키마: 분야/세부분야/대상용어/원어/표준안/해설/사용예.
- **다듬은 말 목록**: 18,320건, 웹 게시. 전용 공공데이터셋은 없고 구 HWP 덤프(2019)와 우리말샘 API(공공누리 1유형)만 있다. 라이선스 표기 미확인이라 **전체를 자동 수입하지 않고, 기술문서에 맞는 항목만 출처를 달아 선별**한다. "디폴트→기본값"은 국어원 자료에 없다. 임의로 넣지 않는다.

### 1.3 통제 한국어 학술 연구

- Hong & Kim (2008, PACLIC 22): 어휘 제한 없이 작성 규칙만으로 MT 품질 +4.25%. 효과 순위: 중의 표현 제거 +25%, 주술 불일치 +21%, 이중 주어 +20%, 주제어 조사 +12.5%, 구두점 +12.5%.
- 함수진·유수린 (2010): `-되다` 구문 1,473개 중 16% 오역. 수동과 상태변화 혼동.
- 이성화·김세현 (2018): 생략 주어 복원 / 복합명사 명확화 / 문장 구조 단순화.
- 공통 결론: **어휘 제한보다 주어 명시, 중의 제거, 복합명사 풀기, 문장 단순화, `-되다` 명확화**가 효과적이다. KSTE 규칙 우선순위의 근거다.

### 1.4 가독성 수치

- 한국어에는 Flesch급 공인 공식이 없다.
- 인터넷의 "8어절 매우 쉬움 / 21어절 어려움" 표는 원출처가 없다. 사용하지 않는다.
- 국립국어원 2003 교과서 연구: 교과서 문장의 51.5%가 10~15어절, 구어는 98.8%가 15어절 이하.
- 안구운동 연구: 복합명사구 띄어쓰기가 읽기 시간에 유의한 영향. 명사 연쇄 규칙의 인지적 근거.
- 결론: 어절 수 임계는 **자체 설정값**이며 국어원 근거가 아님을 문서에 명시한다. 기본값은 교과서 분포 중앙(10~15어절)을 기준으로 잡는다.

### 1.5 구현 기술

| 분석기 | Node 직접 | Windows | 피동·어미 세분 | 라이선스 | 판정 |
|---|---|---|---|---|---|
| Kiwi (kiwi-nlp / kiwipiepy) | WASM 가능 (실측) | wheel, npm 모두 즉시 | 가능 (실측) | Apache-2.0 | **채택** |
| mecab-ko | 불가 | wheel | 가능 | 혼합 | Python 대안 |
| KoNLPy | 불가 | Java 필요 | Komoran만 | 혼합 | 비권장 |
| khaiii | 불가 | 미지원 | 가능 | Apache | 제외 |
| bareun | REST 서버 | 서버 | 가능 | 상업 유료 | 보조 |

Kiwi 실측 사항:
- 로딩 5.5초(모델 110MB). hook마다 재로딩 금지. 상주 워커 또는 결과 캐시 필요.
- 분석 속도 약 9천 토큰/초.
- `splitIntoSents` 반환 스팬은 UTF-8 바이트 오프셋. 토큰의 `sentPosition`으로 문장을 묶는다.
- 선택 인자에 `undefined`를 넘기면 WASM이 중단된다. `Match.allWithNormalizing` 등 명시.
- 명사 연쇄는 형태소가 과분할되므로(제어/반, 절차/서) 형태소 수가 아니라 **어절 수**로 센다.
- 용어 통일표를 `userWords`로 주입하면 복합 용어가 한 토큰으로 유지된다. 실측 확인.

선행 사례:
- `hanlint`(Python/Node, 의존성 0, 정규식): 번역투, 명사 나열, 이중피동, 지시어. 가장 가까운 선행.
- `MuncheKit`(TypeScript, 규칙 500+, 정규식): Kiwi 연동은 계획 단계.
- `looks_like_korean`: Claude Code 플러그인 형태의 한국어 문체 검사기. 구조 참고.
- `sjtower/ste-plugin`, `JAICHANGPARK/ASD-STE100`: 영어 STE 플러그인. hooks 구조 참고.
- 사용 금지: `py-hanspell`류 네이버·부산대 API 스크래퍼(약관·안정성).

KSTE의 차별점: 선행 한국어 린터는 전부 정규식이고 STE 구조 규칙(한 문장 한 지시, 조건 선행, 안전지시 3단)이 없다. 영어 STE 플러그인은 5.2·5.4·7장을 프롬프트에만 맡긴다. KSTE는 **형태소 분석 + STE 구조 규칙 + 정보 보존 검사**를 기계 검사에 넣는다.

형태소 증감(수정 후 − 전): `하/XSV +146`, `EC +176`, `VV +163`, `ETM +128`, `JKB +116`, `EF +94`, `JKO +88`, `JKS +51`. 즉 전문가는 **조사·'-하다'·종결어미를 복원해 명사 나열을 완결 문장으로 만든다.** 글은 길어진다. 예: 「제출완료 되어야 함」→「공단 홈페이지로 제출해 주시기 바랍니다」.

주의: 개선안 텍스트에 보고서 해설 문구(「~로 쓴다」, 「띄어 쓴다」, 「명사」)가 일부 섞여 들어가 증가폭이 과대평가됐을 수 있다. 추출기를 고쳐 재측정해야 정확한 수치가 나온다. 방향 자체(짧아지지 않는다, 피동 비율은 안 변한다)는 오염을 감안해도 유지된다.

**설계에 반영한 결론**

1. **문장 길이·피동 비율·연결어미 수는 좋은 글과 나쁜 글을 가르지 못한다.** 국어원 전문가의 수정은 이 지표를 오히려 올린다. 이 셋은 **오류가 아니라 정보성 경고**로 낮춘다. 특히 피동 비율은 장르 기준선(매뉴얼 20%, 기술보고서 33%)과 비교해서만 의미가 있다.
2. **길이 임계값을 실측에 맞춘다.** 절차문: 경고 16 / 오류 20 어절 (LG 매뉴얼 p90 15~18). 서술문: 경고 20 / 오류 25 어절 (개발자 문서 p90 16~25). 원안(12/16, 16/20)은 잘 쓴 매뉴얼의 10~15%를 오류로 잡았을 것이다.
3. **진짜 신호는 "문법 완결성"이다.** 조사 없는 명사 나열, '-하다' 생략 개조식 종결(함./됨./음.), 서술어 없는 문장. 이것을 K2.3·K4.9로 격상해 오류로 둔다.
4. **이중피동은 거의 없다.** 104만 자에서 5건. 규칙은 유지하되(정밀도 높음) 린터의 주력이 아니다.
5. **명사 연쇄 4어절 이상은 잘 쓴 문서에서도 3~11%.** 경고 4 / 오류 6으로 둔다.
6. **어휘 교체**(솔루션→해결책, 바우처→이용권)가 전문가 수정의 큰 부분이지만 패턴으로 못 잡는다. 사전(K1.4·K4.5)의 몫이고, 사전은 사람이 채운다.

### 1.7 전문가 변환 유형 (국어원 1,520쌍, 2026-10-04)

STE와 비교하면 가치는 같고 수단만 다르다. STE가 관사와 "that"을 생략하지 말라는 것과 한국어 전문가가 조사와 '-하다'를 채우는 것은 같은 행동이다. STE 사전(미승인어 1,274개)과 국어원 용어 쌍 811개도 같은 역할이다.

## 2. KSTE 작문 규칙 (초안)

## 3. 사전 설계

### 3.1 파일 구조

```
rules/
  terms.yaml      # 프로젝트 용어 통일표 (사용자 확정, Kiwi userWords로도 주입)
  banned.yaml     # 번역투·중복·명사화 (국어원 출처 필수)
  refined.yaml    # 다듬은 말 선별 (국어원 출처 필수, 80%에서는 경고)
  patterns.yaml   # 형태소 패턴 (피동·이중피동·추측·격식)
  metrics.yaml    # 길이·밀도 임계값
schema/*.json     # 각 YAML의 JSON Schema
```

```yaml

  - preferred: 회생제동

    pos: NNP
    source: 철도차량 용어집 3.2

# banned.yaml
banned:
  - id: K4.5-001

```

### 3.3 사전 운영 원칙

1. 모델은 사전 항목을 **제안만** 한다. 파일에 쓰는 것은 사람이 승인한 뒤다.
2. 모든 항목에 `source` 필수. 없으면 스키마 검증 실패.
3. `terms.yaml`은 프로젝트별, 나머지는 플러그인 공통 + 프로젝트 오버레이.
4. 다듬은 말은 전체 수입하지 않는다. 기술문서에서 실제로 통용되는 항목만 넣는다. (갱신, 내려받다, 누리집은 넣고, "로그인→회원 들어가기"는 넣지 않는다.)

## 4. 린터 아키텍처

### 4.1 2계층 엔진

```
입력 Markdown
  → 전처리: 코드 블록·인라인 코드·URL·표 셀 보호(플레이스홀더), 문장 분리
  → Tier 0 (regex): banned/refined 표면형, 길이, 세미콜론, 쉼표 나열, 경고 식별어, 정보 보존 토큰 비교
  → Tier 1 (Kiwi WASM, 있을 때): patterns 형태소 매칭, 명사 연쇄, EC 수, EF 격식, 피동 밀도, 명사 집합 비교
  → 리포트: JSON + SARIF + Claude용 Markdown
```

- Tier 1은 상주 워커(`worker_threads`)에 모델을 한 번 올리고 소켓/IPC로 질의한다. hook 호출마다 5.5초 로딩을 피한다.
- Kiwi 미설치 시 Tier 0만 돌고, 리포트에 "T1 규칙 N개 미검사"를 명시한다.
- Python 백엔드(`kiwipiepy`)는 선택. 같은 모델·같은 태그라 규칙 코드를 공유한다. 태그는 `tag.split('-')[0]`로 정규화.

### 4.2 리포트 형식 (Claude용)

```
[KSTE] 7 findings (T0 5, T1 2) · T1 active · mode 80%
error  K3.2  L12  "저장되어집니다" → 이중피동. '저장됩니다'
error  K9.1  —    원문 숫자 "30초" 가 결과에 없음
warn   K5.1  L18  17어절 (제한 12). 두 문장으로 나눈다
warn   K4.5  L21  "~에 있어서" → "~에서"
warn   K2.1  L25  명사 연쇄 5어절 "전동기 제어반 전원 공급 장치"
info   K4.4  L30  지시어 "해당" — 대상 확인 필요 (사람 판정)
--- 린터 범위 밖 (사람 확인) ---
K4.2 주어 생략, K5.5 Note 내 지시, K6.4 핵심어 반복
```

마지막 블록이 ASD 경고에 대한 답이다. 기계가 못 본 것을 숨기지 않고 범위를 좁혀 사람에게 넘긴다.

### 4.3 수정 루프

1. 모델이 글을 쓴다 (SKILL.md 규칙 참조).
2. Stop hook이 린터를 돌린다.
3. 위반이 있으면 위반 목록을 그대로 모델에게 돌려준다.
4. 모델은 **지적된 줄만** 고친다. 전체 재작성 금지.
5. 최대 3회 반복. 남은 위반은 사용자에게 그대로 표시한다.
6. K9 정보 보존 오류는 재작성 자체를 되돌리고 원문을 유지한다.

## 5. 플러그인 구조

```
ko-ste/
  .claude-plugin/plugin.json, marketplace.json
  skills/kste/SKILL.md            # 모델용 작문 규칙 (K1~K9, 80% 모드)
  skills/kste/references/         # 규칙별 근거·예문 (국어원 원문 인용)
  commands/kste-check.md          # /kste check [file]
  commands/kste-rewrite.md        # /kste rewrite — 재작성 + 정보 보존 검사
  hooks/hooks.json                # Stop, PostToolUse(Write|Edit *.md)
  hooks/register.js               # /kste on|off|80|strict|pane
  lib/engine/
    preprocess.js, sentences.js, tier0.js, tier1.js, report.js
    kiwi-worker.js                # 상주 워커
  bin/kste.js                     # CLI (CI용, --json --sarif --fail-on)
  rules/*.yaml + schema/*.json
  tests/
    fixtures/violations/*.md      # 규칙별 위반 문장 (각 규칙 최소 5개)
    fixtures/clean/*.md           # 통과해야 하는 문장
    expected/*.json
    engine.test.js                # 탐지율·오탐률 수치 출력
  scripts/install-model.js        # Kiwi 모델 110MB 내려받기 (선택)
```

- Node 20 이상, 의존성: `kiwi-nlp`(선택), `yaml`, `ajv`.
- 한국어 전용. 영어 문서에는 `/kste off`.
- caveman 규칙과 충돌 없음. caveman은 "뭘 뺄지", KSTE는 "남은 문장을 어떻게 쓸지".

## 6. 검증 계획

1. **테스트 코퍼스**: 규칙별 위반 문장 5개 이상 + 정상 문장 5개 이상. 국어원 문서의 나쁜 예·좋은 예 쌍을 그대로 쓴다(출처 표기).
2. **탐지율·오탐률**을 숫자로 낸다. 이 숫자가 "어디까지 믿을 수 있다"의 근거다.
3. **정보 보존 실험**: 기술 설명문 20편을 80% 모드와 strict 모드로 재작성하고 핵심 사실 손실률을 측정한다. Ghinda 실험(46.8% / 8.5%)과 비교한다.
4. **Tier 0 vs Tier 1 비교**: 같은 코퍼스에서 Kiwi 유무에 따른 탐지율 차이를 기록한다. 이 차이가 110MB 모델 설치를 권할지 결정한다.
